# AI Research Board 通用信息搜集流程 V1

## 1. 从七月新番人工检索得到的结论

有效的信息搜集不是一次宽泛搜索，而是一个有边界的证据工程。七月新番任务可以拆成：

- 监控对象：无职转生第三季、再见菈菈、穹庐下的魔女、尼古喵喵。
- 研究任务：播出变更、停播/分期、最新单话制作人员、未来更新日历。
- 时间截点：结论截至哪一天；“最新”“下一话”都必须依赖截点。
- 来源层级：官网/官方账号优先，播出机构其次，专业资料站交叉核对，社区片尾表转录只用于补缺。
- 输出约束：每个对象都要有当前状态、已确认变化、下一节点、来源和可信度说明。

因此通用模型是：

```text
监控对象 × 研究任务 × 来源层级 × 时间截点
```

## 2. 通用流程

### 阶段 A：建立研究简报

1. 从项目名称、说明和目标中提取具体监控对象。
2. 把项目关注项转换为可回答的问题。
3. 明确“最新状态”对应的时间截点和时区。
4. 为每个问题定义证据要求，例如：
   - 日期、开放状态、票价、停播：必须优先使用一手或执行机构来源。
   - 单话职员、技术细节：允许专业数据库补充。
   - 社区转录：必须标记为未独立核验。

### 阶段 B：生成检索矩阵

为每一个“对象 × 任务”生成多语言、跨渠道查询：

```text
对象 + 任务 + 官方 + 最新
对象 + 任务 + official + latest
对象 + 任务 + 官方社交账号/视频频道
对象 + 任务 + 论坛/专业数据库/个人博客
```

不能假定一个综合首页能够覆盖项目中的全部对象和问题。

### 阶段 C：构建来源组合

| 层级 | 典型来源 | 用途 | 默认可信度 |
|---|---|---|---|
| Primary | 官网、政府、官方公告、官方账号、原始话数页 | 确认事实 | 高 |
| Operator | 电视台、售票方、交通运营方、发行平台、任务执行机构 | 确认实际执行时间和状态 | 高 |
| Specialist | 专业资料库、成熟行业媒体、结构化日历 | 交叉核对和补字段 | 中 |
| Community | 论坛、个人页面、片尾表转录、社区讨论 | 只用于补缺 | 低 |

### 阶段 D：采集与标准化

每条证据至少保留：

- 对象和研究任务
- 标题、核心事实、发生时间、发布时间
- 来源名称、URL、平台、证据层级
- 是否是一手陈述
- 原语言和输出语言
- 本次采集时间

网页原文不能直接作为卡片正文，必须先提取与研究任务相关的事实。

### 阶段 E：交叉核验

1. 相同事实由多个来源确认时合并来源。
2. 一手来源与二手来源冲突时优先一手来源，并记录冲突。
3. 只有二手或社区来源时，可以输出，但必须标记“推断”或“未独立核验”。
4. “没有找到公告”只能表述为“截至当前截点未检索到”，不能等同于“确定没有变化”。
5. 所有未来日期必须区分官方确认和按固定周期推算。

### 阶段 F：二次信息整理

输出内容应回答决策问题，而不是罗列网页：

```text
当前状态
最新确认变化
关键证据与来源
下一时间节点
可信度与限制
```

同一结论采用多个来源时，卡片只显示一个来源入口，悬停后展开完整来源列表。

### 阶段 G：历史比较

- 与上一次快照逐项比较。
- 标出时间、状态、价格、地点、人员等字段变化。
- 冲突统一进入右侧变化中心。
- 每次更新作为一个时间批次卡包保存。

## 3. 故障处理

系统必须区分：

1. 来源请求失败：没有取得正文。
2. 取得正文但与任务不相关：没有匹配证据。
3. AI 返回格式错误：自动修复并重试。
4. AI 重试仍失败：保留来源提取事实，使用本地跨语言规则分类，并明确标记需要人工确认。
5. 来源之间互相矛盾：输出冲突，不静默选择其中一个。

禁止用统一的“当前来源未提供可确认的信息”掩盖上述不同原因。

## 4. 软件实现映射

- `research-skills/general-information-research/SKILL.md`：内置研究技能的单一规范来源，规定完整流程、证据等级、输出契约和质量门禁。
- `research-skill.ts`：按 UTF-8 加载并校验技能，再结合当前项目编译对象、任务、矩阵、语言和截止时间等项目技能实例。
- `research-workflow.ts`：提取对象、生成检索矩阵、定义证据层级。
- `source-discovery.ts`：按矩阵发现官网、账号、平台、专业站和社区来源。
- `ai-client.ts`：把研究矩阵、证据层级、截点和输出规范写入搜索及综合提示词。
- `feed-service.ts`：采集已保存来源，并在每次更新时额外执行完整矩阵网页研究；保留来源层级、跨来源整理、生成批次卡包。
- `information-memory.ts`：比较历史事实并记录变化和冲突。

## 5. 验收标准

- 多对象项目不会只搜索项目总称。
- 每个对象和关注项都至少执行一组查询。
- 日期与状态结论优先引用一手或执行机构来源。
- 社区来源不会被伪装成官方确认。
- 每张卡片保存所有采纳来源。
- 输出使用设置语言，并保留原文链接。
- AI 失败时仍能看到提取事实和真实失败原因。
- AI 返回空占位卡时，必须优先用已采集的矩阵证据替换；无证据时输出覆盖审计而不是模糊占位语。
- 模型输出必须通过技能合规审计：关注项数量、对象覆盖、来源索引和占位文本任一不合格时自动修复。
- 未来时间明确标记“官方确认”或“根据周期推算”。
