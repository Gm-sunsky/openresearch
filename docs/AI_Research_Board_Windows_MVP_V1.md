# AI Research Board Windows 版 MVP 设计方案 V1.0

## 1. 产品定位

AI Research Board 是一个 Windows 桌面端的 local-first 信息项目管理工具。用户不是“搜索一次信息”，而是“创建一个长期维护的信息项目”。系统围绕项目持续收集、整理、更新和可视化信息，形成可增长的个人知识板。

### 1.1 产品目标

- 让用户用自然语言创建一个信息项目
- 自动把项目转成可执行的监控规则
- 持续收集 RSS 和网页信息源
- 将新内容整理成可移动、可追踪的卡片
- 让用户在白板上快速理解“当前态势”

### 1.2 第一版不做的事

- 多人协作
- 云同步
- 账号系统
- 社交媒体抓取
- 视频分析
- 移动端
- 商业订阅

## 2. 技术前提

### 2.1 检测到的前端栈

- Electron
- React
- TypeScript
- Tailwind CSS
- SQLite（本地）

### 2.2 架构原则

- 本地优先
- 数据可离线持久化
- 桌面端 UI 以信息密度优先
- AI 能力先做“项目创建、摘要、分类、变化检测”
- 后端能力先做“抓取、解析、存储、定时更新”

## 3. 视觉方向

### 3.1 设计关键词

- 暖灰纸张
- 深墨侧栏
- 单一珊瑚红强调色
- Linear 式克制
- 中文界面
- 轻图层、少装饰、少渐变

### 3.2 视觉规则

- 背景使用暖灰，不使用纯白
- 侧栏使用深墨色，作为稳定信息锚点
- 强调色只保留一种珊瑚红，用于主按钮、状态点、选中态
- 卡片尽量扁平，减少厚重阴影
- 板面留足空白，不用密集大卡片堆叠
- 字体采用中文可读性高的系统外观方向，避免 Inter / Roboto / Arial 感

## 4. 信息架构

### 4.1 主层级

1. 应用级导航
2. 项目列表
3. 项目白板
4. 项目详情面板
5. 设置与同步占位入口

### 4.2 项目对象

每个项目是一个独立工作空间，包含：

- 项目目标
- 监控对象
- 信息源
- 卡片集合
- 定时更新策略
- AI 生成的观察结论

## 5. 1440x900 主工作区布局

### 5.1 布局分区

推荐采用三栏结构：

- 左侧导航栏：280px
- 中央白板区：自适应
- 右侧详情栏：320px，可折叠

### 5.2 结构说明

#### 左侧导航栏

用于稳定切换项目和创建新项目。

内容从上到下：

- 产品名与版本状态
- `+ 新建项目` 主按钮
- 项目列表
- 最近更新入口
- 设置入口

#### 中央白板区

用于展示当前项目的卡片布局。

内容从上到下：

- 项目标题
- 一行项目摘要
- 视图工具条
- 白板画布

#### 右侧详情栏

用于查看当前选中卡片、项目设置和来源信息。

内容从上到下：

- 选中项标题
- 来源信息
- AI 摘要
- 变化记录
- 操作按钮

### 5.3 画布密度

- 默认显示 6 到 10 张卡片即可
- 不追求首页“全量曝光”
- 重要内容靠右侧详情补足
- 空白区是白板的一部分，不是缺内容

## 6. 创建项目流程

### 6.1 流程目标

用户输入一句自然语言，系统生成一个可执行项目。

### 6.2 交互步骤

1. 点击 `+ 新建项目`
2. 弹出创建面板
3. 用户输入项目描述
4. 用户选择更新频率
5. 用户确认生成
6. AI 输出项目配置草案
7. 用户可编辑后创建

### 6.3 创建面板字段

- 项目名称
- 项目描述
- 关注对象
- 信息类别
- 更新频率
- 数据源建议

### 6.4 AI 输出目标

系统应把自然语言转成以下结构：

- 项目名
- 目标
- 监控对象
- 信息类别
- 推荐信息源
- 检查频率

### 6.5 默认文案

- 标题：`创建信息项目`
- 主输入提示：`例如：持续关注 Yorushika 的演出、公告和售票信息`
- 次提示：`系统会自动生成监控对象、信息类别和更新频率`
- 主按钮：`生成项目`
- 次按钮：`返回`

## 7. 白板卡片视觉规范

### 7.1 卡片基础

- 圆角中等
- 高度可变
- 只保留一层轻阴影或细边框
- 卡片标题在上，内容在中，元信息在下
- 卡片拖动后保留轻微位移反馈

### 7.2 卡片尺寸建议

- 小卡：240x160
- 标准卡：300x200
- 信息卡：360x240
- 时间线卡：400x260

### 7.3 卡片类型

#### 新闻卡

展示新闻摘要、来源、时间和重要程度。

#### 网页源卡

展示网站名称、URL、最后检查时间和状态。

#### 事件卡

展示演出、公告、售票、活动等结构化事件。

#### 时间线卡

展示按时间排序的关键变化。

#### AI 分析卡

展示系统对近 7 天或 30 天信息的总结判断。

### 7.4 卡片内容层级

1. 标题
2. 主内容摘要
3. 来源或时间
4. 状态标签
5. 操作入口

### 7.5 卡片状态

- 默认
- Hover
- 选中
- 拖动中
- 更新中
- 异常

## 8. 空状态设计

### 8.1 项目列表空状态

当没有项目时，主区域显示一个清晰的引导面板：

- 标题：`还没有信息项目`
- 描述：`创建一个长期跟踪的主题，系统会自动帮你整理更新`
- 主按钮：`创建第一个项目`

### 8.2 白板空状态

当项目已建但尚无卡片时：

- 标题：`这个项目还没有卡片`
- 描述：`添加信息源后，系统会在下一次检查时自动生成内容`
- 主按钮：`添加信息源`
- 次按钮：`试用示例项目`

### 8.3 无结果空状态

当抓取成功但没有新变化时：

- 标题：`本次没有新变化`
- 描述：`信息源已检查，未发现新增公告或事件`
- 右下角显示上次更新时间

## 9. 关键交互

### 9.1 项目切换

- 点击左侧项目名切换工作空间
- 切换时保留白板滚动位置到项目级别
- 新项目切换后默认居中视图

### 9.2 卡片拖动

- 卡片可在白板中拖动
- 拖动时显示轻量对齐辅助线
- 松手后自动保存位置
- 不做复杂的吸附动画

### 9.3 卡片选择

- 单击选中卡片
- 右侧详情栏同步更新
- 双击进入编辑或打开来源

### 9.4 更新触发

- 手动点击“立即检查”
- 后台定时检查
- 新内容到达时自动生成新卡片

### 9.5 变化提示

- 新卡片进入时短暂高亮
- 右上角显示未读数量
- 更新完成后给出一条简短结果提示

## 12. 交付边界

### 12.1 第一阶段可验收结果

- 能创建项目
- 能看到项目列表
- 能创建和展示白板卡片
- 能拖动卡片并保存位置
- 能读取 RSS 或网页源
- 能定时更新并生成新卡片
- 能在 Windows 桌面端运行

### 12.2 通过标准

- 启动后可进入主界面
- UI 在 1440x900 下不溢出
- 空状态有明确引导
- 核心操作不依赖教程即可理解
- 卡片布局与项目状态可持续积累

## 13. 推荐开发顺序

1. 桌面壳体和基础布局
2. 项目列表与项目创建
3. 白板和卡片组件
4. SQLite 数据层
5. RSS 和网页抓取
6. AI 摘要与分类
7. 定时任务与更新提示

## 14. 给 Codex 的实现指令

- 先搭建 Electron + React + TypeScript 的基础壳
- 先做 1440x900 主工作区，不要先堆复杂设置页
- 先做项目列表、创建项目、白板卡片三件事
- UI 风格必须保持暖灰纸张、深墨侧栏、珊瑚红强调色
- 不要引入泛滥阴影、紫色渐变、默认系统味
- 所有页面都应先有空状态，再补数据态
